# Debounce VS Throttling
둘 모두 연속적인 이벤트를 처리하기위한 기술인 공통점이 있다.
<br>
차이점으론 실행하지 않는 이벤트의 범위와 그것을 어떻게 처리하는지에 있다.
Debounce는 실행하는 이벤트에 연속하는 모든 이벤트를 무시한다. 반면 Throttling은 일정 시간동안 연속하는 이벤트 중 하나만 실행한다.
예를 들어, 영화 예메 페이지에서 예메버튼을 1초에 두 번 씩 100초간 눌렀다고 하자. 그렇다면 Debounce로 처리할 경우 100초간 처리하는 클릭 이벤트는 1개다. 반면 10초에 한 이벤트를 처리하도록 설정한 Throttling의 경우 10개의 클릭 이벤트를 처리한다.

# Cookie
서버가 클라이언트를 식별하기 위해 브라우저에 저장하는 데이터다.
로그인을 유지하고 사용자의 선호를 조사하는 등 서버는 사용자를 식별하고 있을 필요가 있다. 하지만 서버는 기본적으로 한 번 요청에 응답하면 클라이언트와 연결을 끊어 식별하지 못한다(Stateless & Connectionless). 따라서 주민등록증과 같이 사용자와 관련된 정보를 담아 브라우저에 발급해준다. 브라우저가 요청과 함께 쿠키를 제시하면 서버가 사용자를 식별하여 개인화된 딥웹 서비스를 제공해줄 수 있다.

# Context-API
컴포넌트에게 값을 전달할 때 props를 사용하지 않아도 된다.\
하나의 값이 컴포넌트를 하나만 거칠 때를 주로 다뤘다.
그러나 여러개의 컴포넌트를 거치거나 여러 컴포넌트가 같은 값을 필요로 할 때 복잡해질 수 있다. (prop drilling이라 한다)

전역 상태 
prop을 전역변수처럼 사용해 자식 컴포넌트에서 여러번 전달 없이 바로 꺼내쓸 수 있는 기능
(Provider에 묶인 컴포넌트의 자식은 값을 공유할 수 있는 느낌)
